## 0. 一句话

把 dsh-blog 从「能用的工厂」变成「好用的写作台」：三栏编辑、AI 对话、修改提案、本地预览，一屏完成改、看、发。

---

## 1. 目标与非目标

### 1.1 v2.0 目标

- Tab 收敛为 **起笔 / 落墨 / 阅卷 / 立规**，最前面是“开始写新文章”的入口，不再按“文章/生产/发布/状态”切碎。
- 写作页改为三栏：**左骨架、中正文/预览、右 AI 对话**；右栏默认展开、可收起。
- AI 修改采用 **提案制**：不直接改文件，弹窗双栏对比，人确认后写入并保存版本。
- 编辑页内直接 **本地预览** 构建后的 GitHub Page，并可从预览处发布。
- 站点页可看 **整站预览**、发布历史、线上地址、构建告警。
- 设置页可读写站点配置，诊断分组。
- 后端补齐 **AI 会话、消息、提案** 的基础接口；AI 能力先做最小可用，细节留 v2.1。

### 1.2 非目标（v2.0 不做）

- 富文本编辑器、多人协作、评论、多租户。
- 完整的 AI 编辑策略（选区改写、局部接受、按段勾选）——v2.1。
- 文章模板市场、主题市场、插件市场。
- 移动端原生体验（只做响应式可用）。
- 真正的流式输出（先做非流式，接口预留）。
- 自动选题、自动发布策略调整。

## 2. 关键决策

| # | 决策 | 理由 | 可逆性 |
|---|---|---|---|
| D1 | Tab 只留 起笔/落墨/阅卷/立规 | Tab 表达“我在做什么”，不罗列功能；起笔是默认入口 | 中 |
| D2 | 生产/队列/选题收进写作页，不单开 Tab | 它们都是“产生新文章”，不该和“改文章”分家 | 高 |
| D3 | 写作页三栏：骨架 / 正文 / AI | 左定位、中写作、右协作，职责单一 | 中 |
| D4 | 右栏默认展开、可收起 | 写作时需要宽度，AI 是高频动作 | 高 |
| D5 | AI 只提提案，不直接写文件 | 避免改坏稿子；人确认才落地 | 低 |
| D6 | 提案用双栏对比（原有/新内容），不做行级 diff | 整节改写时并排更直观 | 高 |
| D7 | 每次接受自动存版本 | 可回滚，和现有版本系统一致 | 低 |
| D8 | 本地预览在编辑页内，不跳页 | 形成“改→看→发”闭环 | 高 |
| D9 | 预览默认本地构建，线上另给按钮 | 线上有部署延迟和缓存 | 高 |
| D10 | AI 会话持久化到 `.blog/chat/` | 刷新不丢，和 job 一样可恢复 | 低 |
| D11 | 提案协议走 JSON，解析失败降级纯文本 | 模型输出不稳，不能阻塞对话 | 高 |
| D12 | 继续 GitHub Flow，不引入其他流程 | 分支保护已开，CI 已就绪 | 低 |

## 3. 假设与待确认

### 3.1 默认假设（未确认前按此执行）

- 现有内容目录、构建、部署、流水线不变，v2.0 只动 UI 与新增对话能力。
- 本地预览由 Host 提供静态服务，产物写到 `.blog/preview/<buildId>/`，不覆盖 `docs/`。
- 预览构建复用 `buildSite`，但输出目录可配置。
- AI 会话绑定一篇文章（`slug`），也支持全局会话（`slug: null`）。
- 提案只支持“整节替换”，第一版不做按段勾选。
- 界面语言跟随 DSH locale，英文词条在 v2.0 补齐主要交互。

### 3.2 待确认

1. 本地预览是“点一次构建一次”，还是“编辑时自动增量构建”？默认前者。
2. 站点页的整站预览用本地构建还是线上 iframe？默认本地，提供“打开线上”。
3. AI 会话是否允许跨文章共用上下文？默认不共用。
4. 提案被接受后，是否自动触发预览刷新？默认是。

## 4. 产品形态

### 4.1 四个 Tab

| Tab | 内容 | 人的动作 |
|---|---|---|
| 起笔 | 一句话输入，开始一篇新文章 | 输入 brief，回车或点“开始写作” |
| 落墨 | 文章列表、三栏编辑器、导入、生产入口 | 写、改、让 AI 改、预览、发布 |
| 阅卷 | 整站预览、发布历史、线上地址、构建/自检 | 看整站、发布、回滚 |
| 立规 | 站点、部署、模型与搜索、工厂、诊断 | 配置、体检 |

「起笔」是默认首页，也是唯一的主入口：打开插件先看到输入框，输入完直接进写作页。

### 4.2 起笔页

一个页面只做一件事：把一句 brief 变成一篇文章的起点。

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│                   今天写点什么？                            │
│                                                            │
│   ┌──────────────────────────────────────────────────┐     │
│   │ 写一篇关于 Agent 做内容工厂的长文，面向独立开发者  │     │
│   └──────────────────────────────────────────────────┘     │
│                                                            │
│     [开始写作]   或  [仅新建空白稿]   [从选题开始]          │
│                                                            │
│   最近：                                                    │
│   · 上次的标题                       · 3 篇待审             │
└────────────────────────────────────────────────────────────┘
```

- 中间一个大输入框，自动聚焦，支持多行（Shift+Enter 换行，Enter 提交）。
- **开始写作**：用 brief 创建一个 job/文章，跳到写作页，并自动触发流水线。
- **仅新建空白稿**：只建草稿，不跑 AI，跳到写作页。
- **从选题开始**：跳到落墨页的选题面板（复用现有 topics）。
- 底部“最近”只放三样：上次编辑的文章、待审数量、最近发布；不做历史列表。
- 没有多余设置、没有参数面板；复杂选项都在写作页里。

跳转行为：

1. 输入 brief → 创建 job（`brief`）和占位文章
2. 立刻切到「落墨」Tab，选中这篇文章
3. 落墨页显示流水线进度，右栏 AI 可继续补充
4. 跑完进入待审，用户在中栏看稿、右栏看门禁

### 4.3 落墨页布局

```
┌────────────┬──────────────────────────────┬──────────────┐
│ 左：骨架    │ 中：正文 / 本地预览           │ 右：AI 对话   │
│            │                              │              │
│ 文章列表    │ [编辑] [预览]                 │ 消息流        │
│ 本文大纲    │ 标题 / 分节                   │ 快捷指令      │
│            │                              │ 输入框        │
└────────────┴──────────────────────────────┴──────────────┘
```

- 左栏固定 240–280px，可折叠。
- 中栏自适应，正文最大阅读宽度约 720px。
- 右栏 320–380px，默认展开，可收起。
- 窄屏：左栏变抽屉，右栏变底部抽屉。

### 4.4 修改提案

```
┌──────────────────────────── 修改提案 ────────────────────────────┐
│ 第二节：为什么需要门禁                                            │
│                                                                  │
│ ┌──────────── 原有内容 ────────────┐ ┌──────────── 新内容 ───────┐ │
│ │ 门禁是为了防止低质量内容…        │ │ 门禁是一组自动检查，       │ │
│ │                                  │ │ 用来在人工审稿前挡掉…      │ │
│ └──────────────────────────────────┘ └───────────────────────────┘ │
│                                                                  │
│                        [放弃]  [接受并保存版本]                    │
└──────────────────────────────────────────────────────────────────┘
```

- 顶部写清目标（章节/段落）。
- 两栏等高滚动，可选同步滚动。
- 接受后写入正文 + 版本快照；放弃不改任何文件。

### 4.5 本地预览

- 中栏切到「预览」，iframe 加载 `.blog/preview/<buildId>/`。
- 顶部：页面选择（当前文章/首页/关于）。
- 底部：发布按钮、构建时间、告警。
- 发布后提示线上地址，不自动跳走。

### 4.6 阅卷页

- 顶部：线上地址、最近构建、发布状态。
- 主体：整站 iframe 预览，页面切换。
- 右侧：发布历史、构建告警、自检结果。
- 操作：构建、发布、打开线上。

## 5. 架构

```
Client（React 面板）
   │  fetch /blog/*
Host 插件（ESM）
   ├─ chat/
   │   ├─ sessions.js        会话 CRUD、持久化
   │   ├─ messages.js        消息、调用 llm
   │   └─ proposals.js       提案解析、接受/放弃
   ├─ preview.js             预览构建与静态服务
   ├─ settings.js            site.json 读写与校验
   └─ 现有：jobs/pipeline/build/deploy/versions/topics/budget/cost
```

**边界**：

- Client 不直接读写文件，只调 Host；会话与提案由 Host 落盘。
- AI 调用统一走 `ctx.llm`，不新增 provider。
- 提案写入复用 `writeArticle` + `writeVersion`，保证版本与锁。

## 6. 数据模型

### 6.1 目录新增

```

  .blog/
    chat/
      <sessionId>.json      # 会话元信息 + 消息
    proposals/
      <proposalId>.json     # 提案原文、目标、状态
```

`.blog/` 继续 gitignore。

### 6.2 会话

```json
{
  "schemaVersion": 1,
  "id": "chat-<uuid>",
  "slug": "agent-content-factory",
  "title": "改第二节",
  "createdAt": "...",
  "updatedAt": "...",
  "messages": [
    { "role": "user", "content": "把第二节改具体", "at": "..." },
    { "role": "assistant", "content": "我改了…", "proposalId": "p-...", "at": "..." }
  ]
}
```

### 6.3 提案

```json
{
  "schemaVersion": 1,
  "id": "p-<uuid>",
  "sessionId": "chat-...",
  "slug": "agent-content-factory",
  "target": { "type": "section", "heading": "为什么需要门禁" },

  "after": "新文",
  "status": "pending",
  "createdAt": "...",
  "resolvedAt": null
}
```

### 6.4 设置

复用 `site.json`，新增可写字段白名单：`title`、`description`、`url`、`basePath`、`author`、`lang`、`nav`、`budget`、`deploy`。

## 7. AI 对话

### 7.1 会话生命周期

- 打开文章 → 自动绑定该 slug 的最近会话；没有则新建。
- 会话列表按 `updatedAt` 排序。
- 关闭会话只归档，不删消息。
- 刷新页面后从 `.blog/chat/` 恢复。

### 7.2 消息流程

```
用户输入
  → POST /blog/chat/sessions/:id/messages
  → Host 组装上下文（文章标题、大纲、当前节、选中文本）
  → ctx.llm.prepareCall
  → 解析回复：纯文本 或 { reply, proposal }
  → 写会话
  → 返回 { reply, proposal? }
```

### 7.3 提案解析

- 模型被要求输出 JSON：`{"reply":"...","proposal":{"target":{...},"before":"...","after":"..."}}`
- 解析失败：整段当 `reply`，不生成提案。
- `before` 必须能在正文中定位到，否则提案标记 `stale`，前端提示“原文已变化”。

### 7.4 接受与放弃

- 接受：按 `target` 定位 → 替换 → `writeArticle`（带 version 锁）→ `writeVersion` → 提案 `accepted`。
- 放弃：提案 `rejected`，正文不变。
- 冲突：409，提示重新加载。

### 7.5 上下文范围（v2.0）

- 文章标题、摘要、大纲
- 当前节全文
- 选中的文本（最多 2000 字）
- 最近 10 条消息

不做：全站历史、其他文章全文。

## 8. 本地预览

### 8.1 构建

- `POST /blog/preview/build` 异步构建到 `.blog/preview/<buildId>/`
- 复用 `buildSite`，增加 `outDir` 参数
- 返回 `{ buildId, status }`，前端轮询
- 构建失败保留上次成功产物

### 8.2 服务

- `GET /blog/preview/:buildId/*` 静态返回
- 同源 + 鉴权；只读；禁止路径穿越
- 默认加载文章页，可切首页/关于

### 8.3 发布

- 预览页底部「发布」→ 复用现有 publish/build/deploy
- 发布后显示线上地址与 commit
- 失败进 `pending-push`，提示重试

## 10. API

```
# 起笔
POST   /blog/start                      { brief, mode: "produce" | "blank" }

# 会话
POST   /blog/chat/sessions              { slug }
GET    /blog/chat/sessions?slug=
GET    /blog/chat/sessions/:id
DELETE /blog/chat/sessions/:id
POST   /blog/chat/sessions/:id/messages { content, selection? }

# 提案
POST   /blog/chat/proposals/:id/accept  { version }
POST   /blog/chat/proposals/:id/reject

# 预览
POST   /blog/preview/build              { slug }
GET    /blog/preview/:buildId/*
GET    /blog/preview/status/:buildId

# 站点 / 设置
GET    /blog/site/summary
GET    /blog/settings
PUT    /blog/settings                   { title, description, url, basePath, ... }
```

所有路由：`connection.requestRejection` + 同源校验 + 入参白名单。

## 13. 测试策略

- **单元**：会话读写、提案解析、`stale` 检测、设置校验、预览路径安全。
- **集成**：mock `llm` 返回文本/提案，跑会话→提案→接受，断言正文与版本。
- **前端**：不引入重型测试框架；组件关键逻辑抽成纯函数测试。
- **手动清单**：三栏收放、预览发布、AI 改稿接受/放弃、刷新恢复。
- CI 不联网、不调真实模型。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| AI 提案 JSON 不稳定 | 高 | 解析失败降级纯文本；提案可选 |
| 提案与正文错位 | 中 | `before` 定位失败标 `stale`；写入用 version 锁 |
| 预览构建慢 | 中 | 异步 + 轮询；缓存最近成功产物 |
| 三栏挤压正文 | 中 | 右栏可收起；最小宽度；窄屏抽屉 |
| iframe 鉴权 | 中 | 同源 + requestRejection；预览路由只读 |
| UI 改动面大 | 高 | M6–M11 分批；每批独立可合并 |
| 英文词条遗漏 | 低 | 先补主路径；其余保持中文兜底 |

## 16. 开发顺序理由

先 M6 骨架，因为所有后续页面都挂在三栏与 Tab 上；再 M7 预览，让“改完能看”先闭环；再 M8/M9 的对话与提案，因为它们是新能力、风险最高；最后 M10 站点/设置与 M11 收尾。

如果先做 AI 再做 UI，会重复改布局；如果先做站点页，编辑器的信息架构还没定，容易返工。

## 18. GitHub 项目管理

### 18.1 仓库与分支

- `main` 唯一长期分支，保护已开启：PR + `test (20)` / `test (22)` + 禁止强推。
- 分支命名：`feat/<issue>-<slug>`、`fix/<issue>-<slug>`、`docs/<slug>`、`chore/<slug>`。
- Conventional Commits；squash merge。

### 18.2 工作项

- 一个任务一个 issue，标题 `[M6-1] ...`，正文写验收标准。
- Labels：`type:*`、`area:ui` / `area:chat` / `area:preview` / `area:host` / `area:docs`、`priority:*`。
- Milestone M6–M11；看板列 Backlog / Ready / In progress / In review / Done。

### 18.3 PR

- 关联 issue、改了什么、为什么、怎么验证、截图、风险。
- 一个 PR 只做一件事；尽量 < 400 行。
- CI 绿才合并。

### 18.4 CI

- 沿用 `.github/workflows/ci.yml`：Node 20/22 → `npm ci` → `npm test` → `npm run build` → `npm pack --dry-run`。
- 前端构建产物进 `dist/client.js`，CI 校验体积与语法。

### 18.5 发布

| 里程碑 | 版本 |
|---|---|
| M6 | v2.0.0-rc.1 |
| M8 | v2.0.0-rc.2 |
| M9 | v2.0.0-rc.3 |
| v2.0 DoD | v2.0.0 |

流程：release PR 更新 CHANGELOG → 合并 → tag → GitHub Release。

### 18.6 每个 issue 的完成定义

- 测试覆盖新增逻辑；`npm test` 与 `npm run build` 通过。
- 用户可见变化更新文档。
- 不引入回归；PR 已自审并合并。
